3 One Foundry account behind all of it

Read live from Azure. Not a slide.

Who makes the callModelAuthenticated as
My application, to turn a question into a vector {{ config.COSMOS_MODEL }} at {{ config.COSMOS_DIMS }} my signed-in Entra identity
My application, to answer using the retrieved tickets {{ config.CHAT_MODEL }} my signed-in Entra identity
The PostgreSQL server itself, from inside a query {{ config.POSTGRES_MODEL }} at {{ config.POSTGRES_DIMS }} its own managed identity

The first two are an application calling a model, which is ordinary. The third is a database calling a model, which is not. Cosmos never talks to Foundry at all: my code does that and sends the vector along with the query.

No API keys anywhere, and not by choice. Key authentication is switched off on both the Foundry account and Cosmos, and PostgreSQL has password authentication disabled. The azure_ai extension has a setting for an API key and ours is empty.
